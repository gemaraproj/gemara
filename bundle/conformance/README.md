# Bundle conformance test data

Example bundles for the [content check](../README.md#content-check). Each
test case has one fault at most, so every implementation should return the same
result.

Each test case is one JSON file in [`test-data/`](test-data/), named after the test case.
Every byte string is base64-encoded (RFC 4648, standard alphabet, with
padding), so the bytes survive exactly whatever happens to the file's own
whitespace or line endings. Fields:

- `description`: what the test case tests;
- `expect`: the check's result: `ok`, `digest-mismatch`, `malformed-manifest`,
  `unknown-role`, `mismatch`, `missing-layer` or `extra-layer`;
- `legacy`: present and `true` when the test case is a [legacy bundle](../README.md#legacy-bundles).
  The check accepts it; `bundle.cue` rejects it, because producers must not write it;
- `digest`: the digest the caller expects for the manifest (plain text);
- `manifest`: the exact manifest bytes (base64);
- `config`: the config bytes the implementation holds (base64), absent when it
  holds none;
- `files`: the unpacked bundle, as a map from slash-separated path to file
  bytes (base64). A `bundle.json` entry, when present, is a rendering the check
  ignores.

To run a test case, write each entry of `files` under an empty directory, pass the
decoded `manifest`, the `digest`, the decoded `config` (or nothing) and that
directory to your implementation's content check, and compare the result with
`expect`.

The test data files are generated by [`generate.py`](generate.py), which needs only
Python 3, and are committed so implementations can test against the exact
bytes without running it. To regenerate them after changing it:

```
python3 bundle/conformance/generate.py
```

`make test` checks every test case against a minimal reference implementation of
the content check and against the CUE schema.
